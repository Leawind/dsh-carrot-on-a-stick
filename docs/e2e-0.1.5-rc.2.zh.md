## 发现与处置

1. **README 安装流程不成立**：loader 以 **profile 目录**为 baseUrl 解析裸包名——在仓库根 `dsh web --patch ./cordis.yml` 找不到本地包。正确姿势：先把包装进 profile（`pnpm -C ~/.dsh/profiles/<name> add -w <tarball>`；Windows 下 `file:D:/...` 形式会被 pnpm 拼坏，用 tarball），再 `--patch` 加配置。→ 已改文档。
2. **`dsh_list_tools` 全局注册表为空**：0.1.5+ 模型工具挂在 preset/agent 作用域，不在全局表。→ 工具描述已澄清语义（agent 实际可用工具以 toolCalls 为准）；作用域列表需宿主侧 API，留作后续。
3. **存量捞回过度**：真机一次补挂 156 个历史会话（批量持久化写入用户数据）。0.1.5 的 workspaceRegistry 已按 header.cwd 自动索引，该 rc.6 时代 workaround 属过度行为。→ 改为 `reattachOrphans: true` 显式开启，默认关闭。（本次验证已在共享数据里产生过一次补挂——语义与官方 create 流程一致，如需回滚可按工作区 detach。）
4. **`turn/end` 失败必须透出**：模型调用失败时没有任何 assistant 输出，v0.3.0 返回"成功"的空结果。→ `TaskResult.error` 字段 + `turn/end` 非 completed 收场提取 + 无产出兜底；正是它把根因 #5 暴露出来。
5. **`{{model}}` 提示词变量**：`deployment:persona-prefix` 引用 `{{model}}`，其值直接来自 `agent.options.model`——agent-loop **不做**默认解析，默认模型解析发生在 Web 应用层（`agentDefaultModel`）。插件直连 `ctx.agents.create` 时，`provider` 无 `model` 的残缺选择（v0.3.0 默认值正是如此）会让整个 turn 在组装期失败。→ `resolveAgentOptions()`：成对显式配置直接用，否则经 `ctx.agentDefaultModel.currentSelection()` 补全，仍不完整则明确报错；默认 provider 撤空。
6. **池会话不 flush**：官方 `whenIdle` 注释明确"消费者自读存储需自行 flush"；不 flush 的话 durable log 只有 header，重启续接丢历史。→ 任务后对池会话与 resume 会话统一 best-effort flush。
