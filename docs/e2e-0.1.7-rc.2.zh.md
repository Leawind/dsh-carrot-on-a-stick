## 迁移点核对（0.1.5-rc.2 → 0.1.7-rc.2）

- **presets 子系统重构**：`@deepseek-ai/dsh-agent-presets` 包消失，`ctx.agentPresets` 服务由新包
  `@deepseek-ai/dsh-agent-preset-registry` 提供，`mount(ctx, id?)` 签名不变、`list()` 返回的
  `AgentPreset` 仍有 `id`——插件的类型导入换包即可，运行时零改动，真机挂载通过。
- **消息 source 词汇表**：0.1.7 从 `MessageSourceMap` 移除共享 `plugin` kind（"no shared catch-all
  plugin kind"；user 消息的未知 kind 运行时透传但脱契约）→ 插件自造消息改用 `{kind:'user'}`。
- **usage 位置**：0.1.7 的 `assistant/message` 把 `TokenUsage` 挪到事件载荷（`AssistantMessage` 本体
  不再携带）→ 插件两处都读（新载荷优先，旧宿主 `message.usage` 兜底）。
- **`MessageId` 品牌化**：纯数据构造经 `unknown` 转换（编译期事项）。
- **其余宿主面**：`Agent` 五方法、`AgentRegistry.create/resume`、`SessionStore.get/list/flush`、
  `tools.schemas()`、五个消费事件名、`TextBlock`、`snapshotEvents()` 均未变（源码级 diff 核对）。

## 发现与处置

1. **`e2e.ts` 两处探针过时**（非插件问题）：`task_list` 断言仍期望裸数组（结构化输出已包成
   `{tasks:[...]}`）→ 断言已适配；`parsePayload` 取第一条 SSE `data:` 行，而 agent_run 流里
   **先到的是 progress 心跳通知** → 改为优先取带 `result`/`error` 的响应行。
2. **0.1.7 沙箱 ACL 报错（环境相关）**：pwsh 工具在本 workspace 报 `SetNamedSecurityInfoW failed
   (Win32 5): grantWrite`（DSH 文件沙箱对工作区目录授写 ACL 失败）。模型自行降级用只读 `glob`
   完成任务并如实写进总结——turn 正常收敛，插件侧 `tool_result` 透明透出错误。与插件无关，但
   部署 0.1.7 时值得留意（同目录在常驻 0.1.5 下无此问题）。
3. **重复任务挂起（环境相关）**：第二轮重复 `agent_run` 中，模型尝试"扩大访问权限的重试"后事件流
   静止约 10 分钟——升级重试疑似触发 approval 等待且无人应答（隔离 home 无 GUI 应答者）。
   属 ask 策略 × 沙箱 ACL 的环境组合，与 0.1.5 记录中"审批交互是 Roadmap 项"一脉相承；
   插件的同步 `agent_run` 无服务端超时（`taskTimeoutMs` 只覆盖队列任务）时调用方应自带超时。
